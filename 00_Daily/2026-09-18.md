**复盘与思考**

- `str | None` 表示允许空值，不表示允许省略；是否可省略取决于默认值或默认工厂。字符串长度计字符，列表长度计元素；空格算字符，`.strip()` 只去掉首尾空白。
- 需继续巩固模型与字典的访问差异：模型用 `filters.start_year`，导出后的字典用 `result["start_year"]`，不能用 `result.start_year`；导出保留处理后的整数值。
- 澄清草稿中的“返回子类”：`model_validate()` 返回的是所定义子类的**实例**。`model_json_schema()` 返回结构规则，`model_dump()` 返回实例数据。
- JSON Schema 能表达许多类型和约束，但不等于全部 Python 校验逻辑；自定义校验器的业务逻辑不会自动完整转换。`description` 用于说明规则，本地校验仍需保留。参见 [Pydantic 校验器](https://docs.pydantic.dev/latest/concepts/validators/)。
- 澄清校验时机：使用 Pydantic 结构化输出时，解析与本地校验在 `invoke()` 成功返回实例之前完成；不应把直接调用 `with_structured_output()` 理解为自动反复生成直到校验成功。参见 [LangChain 结构化输出](https://docs.langchain.com/oss/python/langchain/models#structured-output)。

### Pydantic

class Request(BaseModel):
`BaseModel` 不是 `Request` 的形参
定义一个叫 `Request` 的类，它继承 Pydantic 提供的 `BaseModel`。继承 `BaseModel` 后，Pydantic 会根据字段声明帮你实现类似的初始化逻辑，并增加运行时校验
`BaseModel` 是 Pydantic 的基础模型类：
它会读取子类中的类型注解：

```
question: str
max_results: int
```

然后自动为 `Request` 提供数据接收、类型转换、校验和导出等能力。

所有字段必填，除非有默认值


fieldval 是在每个字段校验（按顺序）前后执行，而 model 是在所有字段校验前后

还可以自定义检测规则并raise ValueError

Pydantic 既可以约束整个 LangGraph State，也可以单独约束某个节点中 LLM 返回的结构化结果

LangChain 会把其中的字段类型、取值范围、大小限制等转换成 JSON Schema（pydantic 的规则都有对应，`@field_validator` 中自行编写的 Python 逻辑无法被自动转换成 JSON Schema，因此 LLM 默认不知道这些规则，需要通过 `Field(description=...)` 或提示词告诉它，同时仍由本地验证器负责最终检查。），并通过模型原生结构化输出或工具调用机制发送给 LLM，不一定是直接写进普通提示词。

`invoke()` 返回结果后，Pydantic 会再次在本地进行校验；如果校验失败，直接使用 `with_structured_output()` 通常会抛出错误，不会自动循环重试，但可以自己编写重试流程，


但接口或其他节点给你的数据，往往已经是一个字典。这时可以用 `model_validate()`验证字典是否符合我们的约束、执行校验器、返回一个我们定义的 basemodel 的子类

| 方向            | 方法                                       |
| ------------- | ---------------------------------------- |
| 字典 → 模型       | `SearchFilter.model_validate(data)`      |
| JSON 字符串 → 模型 | `SearchFilter.model_validate_json(text)` |
| 模型 → 字典       | `filters.model_dump()`                   |
| 模型 → JSON 字符串 | `filters.model_dump_json()`              |

外部数据不需要是 Pydantic 对象，但它的字段名、值的类型和结构需要符合自定义模型的规则。字段名不一致时，可以手动映射或设置别名；值不必一开始就是目标类型，只要能够通过 Pydantic 的转换与校验，并满足自定义约束即可。
外部数据的字段数量不必与模型完全相同。缺少必填字段会报错，缺少有默认值的字段则使用默认值。多出的字段默认会被忽略，也可以通过 extra 配置：ignore 表示忽略，forbid 表示报错，allow 表示保留。

我通常不需要自己用model_json_schema()导出结构说明，框架会替我在invoke前的with_structured_output()做好
