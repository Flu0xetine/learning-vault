# 并发任务与结果收集

## 本篇概览

本篇比较顺序 `await`、`asyncio.gather()` 和先 `create_task()` 再等待的执行方式，解释为什么 main 暂停时其他任务仍可运行。核心区别在于其他任务是否已经安排调度，而不是有没有写 await；gather 收集的结果按输入顺序排列。默认调度下的时间线用于理解等待重叠，不能解释为 CPU 同时执行多行 Python。

## 学习来源与前置知识

主要来源：[[20_Areas/FastAPI/codes/02-并发.py|02-并发.py]]。等待机制见 [[001-协程与事件循环的等待机制]]。以下示例修正了原文件中字符串返回值对应的类型标注，以及 Task 被加括号调用的问题；原代码文件未修改。

## 用相同的 A、B 比较三种写法

```python
import asyncio

async def task_a() -> str:
    print("A 开始")
    await asyncio.sleep(3)
    print("A 结束")
    return "a"

async def task_b() -> str:
    print("B 开始")
    await asyncio.sleep(2)
    print("B 结束")
    return "b"
```

### 顺序 await：约五秒

```python
async def main0() -> None:
    result_a = await task_a()
    result_b = await task_b()
    print(result_a, result_b)
```

进入 A 时，创建 B 的下一行还没执行。main 等待 A，约三秒后才继续创建和等待 B。事件循环能调度其他已安排的任务，却不能提前执行 main 尚未到达的下一行。

### gather：约三秒

```python
async def main() -> None:
    a, b = await asyncio.gather(task_a(), task_b())
    print(a, b)
```

`gather()` 将传入的协程安排为任务；在这些任务正常完成的示例中，外层 await 等待所有结果。A、B 的等待时间重叠，因此总时间约为较长的三秒。这里讨论的是成功路径，不应把“等待所有结果”理解为任意异常情况下都具有相同语义。

### 先创建 Task，再逐个 await：约三秒

```python
async def main2() -> None:
    tsk_a = asyncio.create_task(task_a())
    tsk_b = asyncio.create_task(task_b())
    result_a = await tsk_a
    result_b = await tsk_b
    print(result_a, result_b)

asyncio.run(main2())
```

Task 已经安排执行，等待 A 时 B 也可获得调度。Task 是对象，应写 `await tsk_a`，原文件的 `await tsk_a()` 会把 Task 当函数调用，导致类型错误。

## 曾经困惑：为什么第二种 await 不暂停 main？

**问题中的前提（已纠正）**：以为并发版本没有暂停 main。

两种写法都会在结果未完成时暂停 main。差别是：直接顺序 await 时 B 尚未创建；先创建任务时 B 已经可以被调度。暂停 main 只暂停它自身的推进，不停止事件循环，也不暂停独立的 B。

原注释还给出了以下两组假设，它们与文件中固定的 A=3 秒、B=2 秒是不同示例：

| 时间 | 假设 A=3 秒、B=1 秒 | 假设 A=1 秒、B=3 秒 |
| --- | --- | --- |
| 约 0 秒 | 创建 A、B；main 等待 A，两者先后运行至等待点 | 同左 |
| 约 1 秒 | B 完成，main 仍在等待 A | A 完成，main 取得 A 结果，开始等待 B |
| 约 3 秒 | A 完成；main 随后 await 已完成的 B，直接取结果 | B 完成；main 取得 B 结果 |

“约 0 秒两者开始”是粗粒度计时，不代表同一时刻执行两行代码。

## 曾经困惑：create_task 后一定要 await 它才开始吗？

原注释“await tsk_a 时事件循环才获得控制权开始执行”只描述了特定代码路径，不能作为通用条件。

```python
async def main() -> None:
    task = asyncio.create_task(task_a())
    await asyncio.sleep(1)
    print("main 继续")
    result = await task
    print(result)
```

在默认非 eager 调度下，创建 Task 后当前代码继续执行；上面的 sleep 让出控制权，A 已可开始，无须先执行到 `await task`。提前用 `create_task()` 安排 C，C 也可以在调度时获得执行机会。

版本与配置边界：Python 提供 eager task factory，较新版本还提供相关参数，可以使任务在创建期间立即开始执行。因此“create_task 永远不立即执行协程”不成立；本篇时间线按默认非 eager 模式理解即可。

## 并发如何发生

事件循环先运行 A；A 挂起后运行 B；B 挂起后等待下一项就绪事件。两段等待可以重叠，并非一个线程同时执行两段 Python。若 A 执行 `time.sleep()` 或长时间计算且不让出控制权，B 就不能在这段时间被该事件循环推进。

## gather 的返回值与解包

```python
results = await asyncio.gather(task_a(), task_b())
# 即使 B 先完成，结果仍是 ["a", "b"]
```

上面片段应放在异步函数内部。返回结果是列表，顺序对应传入顺序，允许元素类型不同。例如，一个任务返回 `"Alice"`、另一个返回 `20`，结果可以是 `["Alice", 20]`。可用 `name, age = await asyncio.gather(...)` 解包到有明确含义的变量，解包并不改变 gather 的结果顺序。

## 复习自测

1. 连写两个 await 一定串行吗？——直接先调用并等待 A、再调用 B 是串行；若此前已创建两个 Task，则等待期间它们可以并发推进。
2. B 先完成，为什么仍排在结果列表后面？——结果按输入顺序收集。
3. main 暂停后，谁让 B 继续？——事件循环调度已经安排的 B。
4. 为什么 `await tsk_a()` 错？——`tsk_a` 已是 Task，应等待对象，不再调用它。
5. 添加 C 会不会自动三任务并发？——需先安排 C，并且各任务在需要等待时能让出控制权；仅创建一个未调度的协程对象不够。
