# 字段校验器与模型校验器

本篇回答：能否在默认校验之外执行自定义函数？什么时候拿到原始输入，什么时候拿到已转换的值？如何检查多个字段之间的关系？

## 从“默认校验后再执行函数”理解 after

本轮提出的问题是：“这里意思就是我们可以在默认的校验完成后额外执行一个自定义函数吗？”

答案是可以，但要区分**指定字段**的内置校验完成与**整个模型**校验完成。`field_validator` 默认模式是 `after`，针对它注册的字段执行，而不是自动等待所有字段完成。

```python
from pydantic import BaseModel, field_validator

class Request(BaseModel):
    question: str

    @field_validator("question", mode="after")
    @classmethod
    def check_question(cls, value: str) -> str:
        value = value.strip()
        if not value:
            raise ValueError("问题不能为空")
        return value

assert Request(question="  hello  ").question == "hello"
assert Request(question="hello world").question == "hello world"
```

`strip()` 只移除首尾空白，不移除中间空格。`@field_validator` 注册函数，`@classmethod` 使第一个参数为模型类 `cls`；例子里无需使用它。

对 `question="   "`，字符串类型检查通过，但去空白后没有内容，自定义规则拒绝它。对 `question=None`，字符串类型检查先失败，该字段的 `after` 函数不会运行。

## before 与 after 的顺序

下面只描述本轮使用的普通 `before`／`after` 模式，不涵盖 `plain`、`wrap` 等高级模式。

```text
字段原始输入
  → 字段 before 校验器
  → 内置类型转换与约束检查
  → 字段 after 校验器
  → 该字段的最终值
```

| 模式 | 接收的值 | 常见用途 |
|---|---|---|
| `before` | 原始输入，可能是任意类型 | 格式预处理；返回值仍需继续接受内置校验 |
| `after` | 已通过该字段内置校验的值 | 业务规则检查、进一步规范化 |

本轮的奇数数量例子：字段为 `int`，自定义 `after` 函数检查 `value % 2`。输入 `"3"` 时函数收到的是整数 3，所以奇数检查可以通过；输入 `"未知"` 时无法转换，函数不会执行。

**必须返回想保存在字段里的值。** 只做检查却忘记 `return value`，函数会隐式返回 `None`；不要指望 `after` 后再自动重做同样的内置类型检查。[校验器与返回值](https://docs.pydantic.dev/latest/concepts/validators/)

## 跨字段关系使用 model_validator

两个年份各自是整数，不代表年份区间有效。需要一起判断“开始年份不能晚于结束年份”。

```python
from typing import Self
from pydantic import BaseModel, model_validator

class SearchFilter(BaseModel):
    start_year: int
    end_year: int

    @model_validator(mode="after")
    def check_year_range(self) -> Self:
        if self.start_year > self.end_year:
            raise ValueError("开始年份不能晚于结束年份")
        return self
```

该 `after` 方法接收已经过字段校验的实例 `self`，所以不写 `@classmethod`；`Self` 表示当前类的实例，Python 3.11+ 可从 `typing` 导入。

| 输入 | 是否进入模型 after | 结果 |
|---|---|---|
| `start_year="2020", end_year="2025"` | 是 | 转成整数后顺序合法，通过 |
| `start_year=2025, end_year=2020` | 是 | 违反跨字段关系，失败 |
| `start_year="未知", end_year=2025` | 否 | 字段解析先失败 |

草稿对“field 在每个字段前后，model 在所有字段前后”的概括，可细化为：字段校验器只处理指定字段；模型 `before` 在模型字段解析前处理原始输入，模型 `after` 在模型字段校验成功后处理实例。字段检查失败不等于其余字段全不检查，Pydantic 可以收集多个字段错误；但整个模型的 `after` 不会因此得到一个成功构造的实例。

## ValueError 与 ValidationError 的分工

在校验器中用 `raise ValueError(...)` 表达业务规则失败；对调用者来说，Pydantic 会把该错误纳入 `ValidationError`。这与直接在普通函数中抛出 `ValueError` 的场景不同。

```python
from pydantic import ValidationError

try:
    SearchFilter(start_year=2025, end_year=2020)
except ValidationError as exc:
    print(exc.errors())  # 可读取错误位置、类型、信息等
```

字段校验失败通常能定位到字段；模型级关系失败不一定对应单个字段。自定义校验器是本地 Python 逻辑，不会因为被注册就自动完整出现在 JSON Schema，见 [[LangChain结构化输出与本地校验]]。

## 复习自测

**问：字段 `int` 的 after 收到字符串 `"3"` 吗？** 答：正常内置解析通过后收到整数 3。

**问：只检查 `start_year` 是整数，能保证年份范围正确吗？** 答：不能，必须结合 `end_year` 检查关系。

**问：校验器能修改数据吗？** 答：能，返回值会影响最终字段或模型；因此返回值本身也是规则的一部分。
