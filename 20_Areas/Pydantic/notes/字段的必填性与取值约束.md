# 字段的必填性与取值约束

本篇回答：一个字段能不能省略、能不能传 `None`、允许哪些值，以及约束作用在哪一层。适用于 Pydantic v2。

## 必填与允许 None 分开判断

| 模型中的声明 | 可以省略 | 可以传 `None` | 省略时的结果 |
|---|---|---|---|
| `name: str` | 否 | 否 | 缺失错误 |
| `name: str = "匿名"` | 是 | 否 | `"匿名"` |
| `name: str \| None` | 否 | 是 | 缺失错误 |
| `name: str \| None = None` | 是 | 是 | `None` |

类型部分规定允许什么值；默认值规定没提供字段时怎么办。`Optional[str]` 与 `str | None` 表达同样的类型含义，也不会凭空增加默认值。

日记中的“所有字段必填，除非有默认值”可作为本轮普通字段的记忆规则；更完整的说法是：没有默认值、也没有 `default_factory` 的普通模型字段是必填的。[字段默认值](https://docs.pydantic.dev/latest/concepts/fields/#default-values)

```python
from pydantic import BaseModel, Field

class Request(BaseModel):
    question: str
    max_results: int = 3
    context: str | None = None
    keywords: list[str] = Field(default_factory=list)

r = Request(question="解释 RAG")
assert r.max_results == 3
assert r.context is None
assert r.keywords == []
```

这里的 `default_factory=list` 在需要默认值时调用 `list()`。本轮基础练习已经分清：如果将 `context` 改为 `context: str | None`，省略它会失败，显式传 `context=None` 才通过。

## Field 同时可以设置默认值、约束和描述

```python
class SearchRequest(BaseModel):
    question: str = Field(min_length=1, max_length=200)
    max_results: int = Field(default=3, ge=1, le=10)
    keywords: list[str] = Field(min_length=1, max_length=5)
```

`question` 和 `keywords` 依然必填：出现 `= Field(...)` 不等于设置了默认值。`description` 也只是说明，不是运行时业务校验规则。

| 参数 | 对应要求 | 例子 |
|---|---|---|
| `gt` / `ge` | 大于／大于等于 | `gt=0` 不含 0；`ge=1` 包含 1 |
| `lt` / `le` | 小于／小于等于 | `le=10` 包含 10 |
| `min_length` / `max_length` | 长度上下限 | 字符串看字符数，列表看元素数 |
| `pattern` | 字符串模式 | `r"^[A-Z]+$"` 要求全部为一个或多个大写英文字母 |

本轮练习中，`max_results="5"` 先转换为整数 5，再通过范围校验；`"20"` 虽能转换成整数，却超过 `le=10`，仍然失败。

## 学习中纠正的两个判断

**当时的理解（已纠正）：这些约束似乎只能限制数值。**

修正：数值大小只是其中一类。字符串可以限制长度和模式，列表可以限制元素数量。判断前先看字段类型和所用参数。

**当时的判断（已纠正）：一个空格的问题与空关键词列表都能通过。**

| 输入片段 | 结果 | 理由 |
|---|---|---|
| `question=" "` | 通过字符串长度约束 | 一个空格也是一个字符 |
| `keywords=[]` | 失败 | 0 个元素，小于最小数量 1 |
| `keywords=[""]` | 通过上面列表的约束 | 有 1 个元素；元素是字符串，尚未要求该字符串非空 |

如果要拒绝纯空白问题，应先去首尾空白，再检查内容，见 [[字段校验器与模型校验器]]。列表长度约束不会自动递归成元素长度约束。

补充复习示例：可以用 `Annotated` 为列表元素单独添加约束。这是整理时补充的说明，原课程尚未系统讲解 `Annotated`。

```python
from typing import Annotated

Keyword = Annotated[str, Field(min_length=1)]

class KeywordRequest(BaseModel):
    keywords: list[Keyword] = Field(min_length=1, max_length=5)
```

现在 `[]` 和 `[""]` 分别因列表为空、元素字符串为空而失败；`[" "]` 仍需额外空白处理。

## Literal 限定选项，嵌套模型限定内部结构

```python
from typing import Literal

class RouteDecision(BaseModel):
    route: Literal["search", "answer"]
    reason: str

class QuestionAnalysis(BaseModel):
    question: str
    decision: RouteDecision

analysis = QuestionAnalysis(
    question="今天上海天气怎么样？",
    decision={"route": "search", "reason": "需要实时信息"},
)
assert isinstance(analysis.decision, RouteDecision)
assert analysis.decision.route == "search"
```

本轮练习确认：`"Search"` 不等于 `"search"`；`reason=""` 仍可通过，因为没有长度要求。嵌套字典会继续接受内层校验，缺少必填的 `reason` 会失败；外层字段齐全不能抵消内层缺失。

## 复习自测

**问：`context: str | None` 与 `context: str | None = None` 差在哪里？**

答：都允许 `None`，只有后者允许省略。

**问：想限制“至少一个非空关键词”，只写 `list[str] = Field(min_length=1)` 够吗？**

答：不够。它只约束列表数量；还需约束每个字符串，并根据需求排除纯空白。
