# 05-外部字段映射与额外字段处理

## 本篇概览

本篇围绕外部数据接入，分别讨论输入容器、字段名称、值的类型，以及字段缺失或多余的问题。通过手动映射、`validation_alias`、`serialization_alias`、`alias` 和 `AliasChoices` 处理名称差异，再用 `extra` 的 `ignore`、`forbid`、`allow` 策略决定额外字段的去留。核心是：外部数据不必预先是 Pydantic 实例或拥有完全相同的字段，但名称匹配、类型转换、必填检查与额外字段处理必须各自满足规则。

## 四个独立问题

| 要检查的内容 | 处理方式 |
|---|---|
| 输入容器 | 字典可交给 `model_validate()`，JSON 文本可交给 `model_validate_json()` |
| 字段名称不同 | 显式映射，或设置输入别名 |
| 值的类型不同 | 可接受的转换可以通过；不能转换或违反约束则失败 |
| 字段缺失或多余 | 缺失由必填／默认值决定；多余由 `extra` 决定 |

因此外部数据不需要预先创建为 Pydantic 实例，也不需要字段数量严格相同；但必须能按照你定义的匹配、转换与校验规则被接受。

## 手动映射或使用别名

假设外部接口用 `query`，内部统一用 `question`。可以先写 `{"question": payload["query"]}` 显式映射，再送入模型。若希望把输入匹配规则写在模型上，可以用 `validation_alias`：

```python
from pydantic import BaseModel, Field

class Request(BaseModel):
    question: str = Field(validation_alias="query")
    max_results: int = 3

request = Request.model_validate({"query": "解释 RAG"})
assert request.question == "解释 RAG"
assert request.model_dump() == {"question": "解释 RAG", "max_results": 3}
```

外部名称变化不会把内部属性改成 `request.query`。

| 参数                    | 作用                |
| --------------------- | ----------------- |
| `validation_alias`    | 指定接收输入时使用的名称或路径规则 |
| `serialization_alias` | 指定按别名导出时使用的名称     |
| `alias`               | 可同时用于输入匹配和按别名导出   |

默认导出通常使用字段名；要按导出别名输出，可以显式设置 `model_dump(by_alias=True)`。输入别名本身不等于输出别名。[别名文档](https://docs.pydantic.dev/latest/concepts/alias/)

如果两种输入名称都可能出现，可使用 `AliasChoices` 明确接收两者：

```python
from pydantic import AliasChoices

class FlexibleRequest(BaseModel):
    question: str = Field(validation_alias=AliasChoices("question", "query"))
```

这里不应把“别名”误解成无条件同时接受所有名称。名称匹配依赖配置；同时出现两个候选名称时还要注意优先级与额外字段规则，不能当成两份数据自动合并。

## 缺失字段与额外字段分别处理

普通模型字段没有默认值／默认工厂时为必填。缺少必填字段会失败，缺少有默认值的字段使用默认值。这部分与 [[02-字段的必填性与取值约束]] 中的 `None` 区别是同一个机制。

多出来的键按 `extra` 处理：

| 配置 | 行为 | 可以用于 |
|---|---|---|
| `ignore`（默认） | 丢弃模型未声明的额外字段 | 只读取外部数据中的目标字段 |
| `forbid` | 将额外字段视为错误 | 捕捉字段拼写错误、限制输入结构 |
| `allow` | 保留额外字段 | 需要保留扩展信息的结构 |

```python
from pydantic import ConfigDict, ValidationError

class StrictRequest(BaseModel):
    model_config = ConfigDict(extra="forbid")
    question: str
    max_results: int = 3

try:
    StrictRequest.model_validate({"question": "解释 RAG", "max_result": 5})
except ValidationError as exc:
    assert exc.errors()[0]["type"] == "extra_forbidden"
```

例子把 `max_results` 拼成了 `max_result`。若使用默认 `ignore`，拼错的键会被忽略，真正的 `max_results` 则取默认值 3；不会因为多给了一个键就补全目标字段。

`allow` 保留额外键并不意味着已经按某个业务类型严格检查这些额外值；若需要约束额外值，还须另行声明规则。[额外字段配置](https://docs.pydantic.dev/latest/api/config/#pydantic.config.ConfigDict.extra)

## 复习自测

**问：传入 `{"query": "RAG？"}` 能自动匹配模型的 `question` 吗？**

答：不能仅凭语义猜测；需手动映射或配置别名。

**问：`extra="allow"` 能让缺失必填字段也通过吗？**

答：不能。额外字段策略与必填检查是两个问题。

**问：外部传入 `"3"` 而模型写 `int`，是否一定失败？**

答：默认转换规则下可能成功；严格模式或其他约束可能拒绝它。
