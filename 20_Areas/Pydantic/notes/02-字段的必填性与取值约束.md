# 02-字段的必填性与取值约束

## 本篇概览

本篇说明字段的必填性、默认值和允许 `None` 之间的区别，重点比较 `Field(default=...)` 与 `default_factory` 的作用及调用时机。随后介绍 `Field` 的数值、长度与模式约束，以及 `Literal`、嵌套模型和 `Annotated` 如何限制选项、内部结构与列表元素。最值得记住的是：允许省略与允许空值是两回事，约束要看作用在哪一层，默认值是否接受校验也需单独确认；本文适用于 Pydantic v2。

## 必填与允许 None 分开判断

| 模型中的声明 | 可以省略 | 可以传 `None` | 省略时的结果 |
|---|---|---|---|
| `name: str` | 否 | 否 | 缺失错误 |
| `name: str = "匿名"` | 是 | 否 | `"匿名"` |
| `name: str \| None` | 否 | 是 | 缺失错误 |
| `name: str \| None = None` | 是 | 是 | `None` |

类型部分规定允许什么值；默认值规定没提供字段时怎么办。`Optional[str]` 与 `str | None` 表达同样的类型含义，也不会凭空增加默认值。

日记中的“所有字段必填，除非有默认值”可作为本轮普通字段的记忆规则；更完整的说法是：没有默认值、也没有 `default_factory` 的普通模型字段是必填的。[字段默认值](https://docs.pydantic.dev/latest/concepts/fields/#default-values)

```python
from pydantic import BaseModel, Field

class Request(BaseModel):
    question: str
    max_results: int = 3
    context: str | None = None
    keywords: list[str] = Field(default_factory=list)

r = Request(question="解释 RAG")
assert r.max_results == 3
assert r.context is None
assert r.keywords == []
```

这里的 `default_factory=list` 在需要默认值时调用 `list()`。本轮基础练习已经分清：如果将 `context` 改为 `context: str | None`，省略它会失败，显式传 `context=None` 才通过。

## Field 的 default 与 default_factory

这两个是 `Field(...)` 的参数，用来回答同一个问题：**创建模型实例时，如果没有提供这个字段，应该用什么值？** 区别在于，一个直接给值，一个给生成值的可调用对象。[官方默认值说明](https://docs.pydantic.dev/latest/concepts/fields/#default-values)

| 参数                | 传入什么       | 字段被省略时怎么做     | 常见用途               |
| ----------------- | ---------- | ------------- | ------------------ |
| `default`         | 一个已经确定的默认值 | 使用这个默认值       | 固定数量、开关、默认名称       |
| `default_factory` | 函数等可调用对象   | 调用它，以返回值作为默认值 | 新列表、新字典、动态生成的时间或编号 |

### default：直接指定默认值

```python
from pydantic import BaseModel, Field

class SearchOptions(BaseModel):
    max_results: int = Field(default=3, ge=1, le=10)

print(SearchOptions().max_results)               # 3：没传，使用默认值
print(SearchOptions(max_results=5).max_results)  # 5：传了，使用传入值
```

只考虑默认值，`max_results: int = Field(default=3)` 与 `max_results: int = 3` 表达的意思相同。使用 `Field` 的便利是可以在同一处继续添加 `ge`、`le`、`description` 等设置。

默认值不是“校验失败后的替代值”。例如这里传入 `max_results=0` 会违反 `ge=1` 而报错，不会自动改成默认的 3。

### default_factory：需要默认值时再调用

```python
class KeywordOptions(BaseModel):
    keywords: list[str] = Field(default_factory=list)

a = KeywordOptions()
b = KeywordOptions()
a.keywords.append("RAG")

print(a.keywords)  # ['RAG']
print(b.keywords)  # []：各次工厂调用产生各自的新列表

c = KeywordOptions(keywords=["LangGraph"])
print(c.keywords)  # ['LangGraph']：已提供该字段，不调用默认工厂
```

这里的执行过程是：

1. 定义类时，把可调用的 `list` 交给 Pydantic 保存；此时没有写 `list()`，所以没有立即创建列表。
2. 创建 `a` 时，没有提供 `keywords`，Pydantic 调用 `list()` 得到一个新列表。
3. 创建 `b` 时，也没有提供 `keywords`，再调用一次 `list()`，得到另一个列表。
4. 创建 `c` 时已经提供 `keywords`，直接处理传入值，不需要调用这个默认工厂。

因此，它不是每次读取 `a.keywords` 时都执行，而是在正常创建实例、需要补这个字段的默认值时执行。

### 为什么写 list，而不是 list()

`list` 是可调用对象；`list()` 是调用后的结果 `[]`。给 `default_factory` 的应当是“以后能调用的东西”，而不是已经产生的结果。

```python
# 正确：交给 Pydantic，之后按需调用
keywords: list[str] = Field(default_factory=list)

# 不正确：这里传进去的是 []，不是可调用的工厂
# keywords: list[str] = Field(default_factory=list())
```

也可以自己写函数：

```python
def make_keywords():
    return ["RAG"]

class PresetOptions(BaseModel):
    keywords: list[str] = Field(default_factory=make_keywords)

print(PresetOptions().keywords)  # ['RAG']
```

对比 `default=make_keywords()`：这个写法会在执行类定义时先调用函数，把返回结果保存为默认值；`default_factory=make_keywords` 则把调用推迟到需要为实例生成默认值时。对于当前时间、动态编号等，这个时机差别尤其重要。

### 几个容易混淆的边界

- **二选一**：同一个 `Field` 不能同时指定有效的 `default` 和 `default_factory`。
- **省略不等于 None**：`KeywordOptions(keywords=None)` 是显式提供了 `None`，不会调用默认工厂；因为声明是 `list[str]`，它会校验失败。要接收 `None`，需要在类型中明确允许。
- **列表不必都写工厂才能安全**：Pydantic v2 对列表这类不可哈希的默认值会为各实例做深拷贝，所以不能把普通 Python 函数的可变默认参数问题直接套到 `Field(default=[])` 上。`default_factory=list` 更明确地表达“按需创建一个新列表”。[可变默认值](https://docs.pydantic.dev/latest/concepts/fields/#mutable-default-values)
- **默认值校验需要区分**：默认情况下，Pydantic 不校验默认值（包括工厂生成的值）。如果希望默认值也接受类型和约束检查，可设置 `Field(..., validate_default=True)`。不要因为为字段写了类型或 `ge`，就认为默认值一定已经检查过。[默认值校验](https://docs.pydantic.dev/latest/concepts/fields/#validate-default-values)

## Field 同时可以设置默认值、约束和描述

```python
class SearchRequest(BaseModel):
    question: str = Field(min_length=1, max_length=200)
    max_results: int = Field(default=3, ge=1, le=10)
    keywords: list[str] = Field(min_length=1, max_length=5)
```

`question` 和 `keywords` 依然必填：出现 `= Field(...)` 不等于设置了默认值。`description` 也只是说明，不是运行时业务校验规则。

| 参数 | 对应要求 | 例子 |
|---|---|---|
| `gt` / `ge` | 大于／大于等于 | `gt=0` 不含 0；`ge=1` 包含 1 |
| `lt` / `le` | 小于／小于等于 | `le=10` 包含 10 |
| `min_length` / `max_length` | 长度上下限 | 字符串看字符数，列表看元素数 |
| `pattern` | 字符串模式 | `r"^[A-Z]+$"` 要求全部为一个或多个大写英文字母 |



## 学习中纠正的两个判断

**当时的理解（已纠正）：这些约束似乎只能限制数值。**

修正：数值大小只是其中一类。字符串可以限制长度和模式，列表可以限制元素数量。判断前先看字段类型和所用参数。

补充复习示例：可以用 `Annotated` 为列表元素单独添加约束。这是整理时补充的说明，原课程尚未系统讲解 `Annotated`。

```python
from typing import Annotated

Keyword = Annotated[str, Field(min_length=1)]

class KeywordRequest(BaseModel):
    keywords: list[Keyword] = Field(min_length=1, max_length=5)
```

现在 `[]` 和 `[""]` 分别因列表为空、元素字符串为空而失败；`[" "]` 仍需额外空白处理。

## Literal 限定选项，嵌套模型限定内部结构

```python
from typing import Literal

class RouteDecision(BaseModel):
    route: Literal["search", "answer"]
    reason: str

class QuestionAnalysis(BaseModel):
    question: str
    decision: RouteDecision

analysis = QuestionAnalysis(
    question="今天上海天气怎么样？",
    decision={"route": "search", "reason": "需要实时信息"},
)
assert isinstance(analysis.decision, RouteDecision)
assert analysis.decision.route == "search"
```

本轮练习确认：`"Search"` 不等于 `"search"`；`reason=""` 仍可通过，因为没有长度要求。嵌套字典会继续接受内层校验，缺少必填的 `reason` 会失败；外层字段齐全不能抵消内层缺失。

## 复习自测

**问：`default=3` 与 `default_factory=list` 分别提供了什么？**

答：前者提供现成的默认值 3；后者提供生成默认值的可调用对象，字段缺失时再调用 `list()`。

**问：`keywords` 有默认工厂，显式传 `None` 会自动变成空列表吗？**

答：不会。`None` 是已提供的值，是否允许由字段类型决定。

**问：`context: str | None` 与 `context: str | None = None` 差在哪里？**

答：都允许 `None`，只有后者允许省略。

**问：想限制“至少一个非空关键词”，只写 `list[str] = Field(min_length=1)` 够吗？**

答：不够。它只约束列表数量；还需约束每个字符串，并根据需求排除纯空白。
